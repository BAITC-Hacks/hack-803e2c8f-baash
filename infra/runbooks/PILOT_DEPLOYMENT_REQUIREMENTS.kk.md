# Пилотты орналастыру талаптары

Бұл — production пилотына арналған пайдалану талаптарының нұсқаулығы. Бөлек [жария демо туралы есеп](PUBLIC_DEPLOYMENT.kk.md) синтетикалық деректері бар тексерілген VPS/домен/HTTPS стендін сипаттайды. Ол операциялық сәйкестендіру провайдерін, бекітілген bucket, өңірлік credentials, RPO/RTO, сақтау мерзімін немесе өлшенген production өнімділігін бермейді. Пилоттың бұл кіріс деректері B07/B08/B10 болып қала береді.

## Репозиторийден тыс алдын ала шарттар

- Мақсатты желі мен хост профилі, DNS атауы және TLS сертификаттарының өмірлік циклі.
- Нұсқаларды бақылаудан тыс сақталатын PostgreSQL, object-storage және backup credentials.
- Бекітілген OIDC issuer, audience және JWKS endpoint, сондай-ақ рөлдер мен өңірлік claims сәйкестендіруі. API `roles`, `realm_access.roles` және `regions`, `region_ids` немесе `region_id` қабылдайды; содан кейін әр аутентификацияланған сұрау рөл мен өңір ауқымына тексеріледі.
- Орындалу ортасына кез келген синтетикалық емес өтініш немесе тіркеме түспей тұрып, құпиялық/құқықтық негіз және сақтау мерзімі туралы шешім.
- Replay жеткізуді ауыстырмас бұрын нақты көрсетілген өңірлік API sandbox және credentials.

## Конфигурация шекарасы

Бекітілген мәндерді тек орналастыру құпияларын басқару арқылы беріңіз:

```dotenv
PULSE109_ENVIRONMENT=pilot
PULSE109_PROFILE=pilot
PULSE109_DATABASE_URL=<managed outside repository>
PULSE109_LOCAL_IDENTITY_ENABLED=false
PULSE109_OIDC_ISSUER=<approved issuer>
PULSE109_OIDC_AUDIENCE=<approved audience>
PULSE109_OIDC_JWKS_URL=<approved JWKS endpoint>
PULSE109_OIDC_ALGORITHMS=["RS256"]
PULSE109_APPROVED_LEGAL_BASIS=<approved value>
PULSE109_APPROVED_RETENTION_CLASS=<approved value>
```

`PULSE109_LOCAL_IDENTITY_ENABLED=false` local, test және demo профильдерінен тыс міндетті. OIDC конфигурациясы болмаса, қолжетімділік `identity_provider_not_configured` арқылы жабылады; bearer token болмаса, `authentication_required` қайтарылады.

## Объектілік қойма шекарасы

Тіркемелер мен replay snapshots `PULSE109_OBJECT_STORAGE_MODE` арқылы жергілікті файлдық жүйені немесе S3-compatible storage таңдайды. Орындалу ортасына қосылу және адаптерлер бар. Тексерілген жария демо жергілікті volumes пайдаланады; жеке S3 провайдері және оның тұрақтылық/қолжетімділік қасиеттері бұл стендте тексерілмеген. Тіркемелер PostgreSQL ішінде өзгермейтін объект сілтемелерін, SHA-256, медиа метадеректерді және иесі болып саналатын өтініш сілтемелерін сақтайды. Storage adapter қабылданбас бұрын write/read/restore хештерін тексеруге, объектілердің өзгермейтіндігін сақтауға, мазмұнын ешқашан журналға жазбауға және бекітілген провайдермен интеграциялық тесттері болуға тиіс. Қазіргі scanner — mock, антивирус емес.

## Релиз, кері қайтару және қалпына келтіру рәсімі

1. Оқшауланған pilot database және object storage атаулар кеңістігін жасаңыз. Demo volumes немесе ортақ интеграциялық базаны пайдаланбаңыз.
2. `alembic -c services/core/alembic.ini upgrade head` орындаңыз; миграциялар тек алға жүреді. Image digest және migration head мәндерін тіркеңіз.
3. Compose services-ті pilot secrets арқылы іске қосыңыз. Трафик жібермес бұрын `/v1/health/ready` ішінде PostgreSQL readiness болуын талап етіңіз.
4. Рұқсат етілген өңір үшін аутентификацияланған smoke checks орындап, тыйым салынған рөл/өңір сұрауы `403` қайтаратынын тексеріңіз.
5. Әр релиз алдында оператор мақұлдаған database backup және өзгермейтін object manifest жасаңыз. Оқшауланған ортада қалпына келтіріп, хештерді тексеріңіз және smoke flow орындаңыз. Репозиторийдегі ешбір мән резервтік көшіру мақсатын бекітпейді.
6. Application images-ті тек схема үйлесімділігі расталған соң кері қайтарыңыз. Қолданылған миграцияны өңдемеңіз және кері айналдырмаңыз. Дерек құрылымы өзгерсе, жаңа алға бағытталған түзету миграциясын пайдаланыңыз.

## Аяқтау критерийлері

Жергілікті Compose және тексерілген жария PostgreSQL демосы синтетикалық жазбалардағы орындалу тетіктерін көрсетеді. Екеуі де production пилотының дәлелі емес. Пилотты орналастыру үшін сыртқы иесінің мақұлдауы және жоғарыдағы әр шарттың орындалу дәлелдері қажет.
