# Резервное копирование, восстановление и проверка целостности

Проверка восстанавливает данные в новую временную базу. Активная база никогда не перезаписывается.

1. Запишите migration head, время отсечения UTC, число строк, хеш манифеста объектов и токен оператора.
2. Выполните `pg_dump --format=custom --no-owner --file pulse109.dump "$SOURCE_DATABASE_URL"`, передав URL через механизм секретов. Сохраните dump в утверждённом зашифрованном хранилище резервных копий.
3. Создайте новую пустую базу для проверки и выполните `pg_restore --exit-on-error --no-owner --dbname "$DRILL_DATABASE_URL" pulse109.dump`.
4. Направьте `PULSE109_DATABASE_URL` на проверочную базу, выполните `make migrate`, затем интеграционные и контрактные тесты.
5. Сравните исходные и восстановленные количества по модулям, хеши неизменяемых исходных записей, последние ID событий, количества outbox/dead-letter, хеши отчётных артефактов и Alembic head.
6. Запишите время начала/окончания и хеши доказательств в индекс релиза; затем удалите только явно названную проверочную базу по утверждённой процедуре администрирования БД.

RPO, RTO, частота резервного копирования, сроки хранения, владелец ключей шифрования и команда восстановления production object store не задаются до утверждения B08/B09. Релиз не может заявлять эти показатели.
