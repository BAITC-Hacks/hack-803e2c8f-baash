# Репетиция релиза и проверка отката

1. Заморозьте контракт, migration head, dependency locks, манифест синтетического демо и model aliases.
2. Выполните `make lint`, `make typecheck`, `make test`, `make contract-test`, `make e2e`, `make build`, `make load-test`, все задачи оценки ML и Compose health/integration tests.
3. Выполните контрольные списки сценариев отказа, восстановления, отката модели/политики и доступности интерфейса.
4. Создайте индекс доказательств релиза. Ответственный за релиз человек проверяет каждый хеш и подписывает индекс через утверждённую систему подписания; репозиторий намеренно не может сам себя одобрить.
5. Зафиксируйте image digests и результаты сканирования. Развёртывайте по неизменяемому digest, наблюдайте ошибки/outbox/адаптер и свежесть данных, затем продвигайте или откатывайте релиз в утверждённое окно изменений.

Критерии выхода исключают утверждения, заблокированные B01–B10: реальную региональную интеграцию, репрезентативное качество модели, национальное покрытие, обязательный SLA, production OIDC, правовые сроки хранения, мощность GPU и RTO/RPO.
