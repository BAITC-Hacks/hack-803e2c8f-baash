# Резервтік көшіру, қалпына келтіру және тұтастықты тексеру

Бұл тексеру деректерді жаңа уақытша базаға қалпына келтіреді. Белсенді базаның үстінен ешқашан жазылмайды.

1. Migration head, UTC бойынша шектеу уақытын, жолдар санын, объектілер манифестінің хешін және оператор токенін тіркеңіз.
2. URL-ді құпияларды енгізу тетігі арқылы беріп, `pg_dump --format=custom --no-owner --file pulse109.dump "$SOURCE_DATABASE_URL"` орындаңыз. Dump файлын бекітілген шифрланған резервтік көшірме қоймасына сақтаңыз.
3. Тексеру үшін жаңа бос база жасап, `pg_restore --exit-on-error --no-owner --dbname "$DRILL_DATABASE_URL" pulse109.dump` орындаңыз.
4. `PULSE109_DATABASE_URL` мәнін тексеру базасына бағыттап, `make migrate`, одан кейін интеграциялық және келісімшарт тесттерін орындаңыз.
5. Бастапқы және қалпына келтірілген модульдердегі жазбалар санын, өзгермейтін бастапқы жазбалардың хештерін, соңғы оқиға ID-лерін, outbox/dead-letter сандарын, есеп артефактілерінің хештерін және Alembic head мәнін салыстырыңыз.
6. Басталу/аяқталу уақытын және дәлел хештерін релиз индексіне жазыңыз; содан кейін БД басқарудың бекітілген рәсімімен тек нақты аталған тексеру базасын жойыңыз.

B08/B09 бекітілгенше RPO, RTO, резервтік көшіру жиілігі, сақтау мерзімі, шифрлау кілттерінің иесі және production object store қалпына келтіру командасы белгіленбейді. Релиз бұл көрсеткіштерге қол жеткізілді деп мәлімдей алмайды.
