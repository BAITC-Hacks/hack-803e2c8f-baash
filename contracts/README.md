# Технический пакет Pulse 109

Пакет сопровождает техническое задание и архитектурный документ.

## Состав

- `openapi.yaml`: базовый внешний и внутренний API приложения.
- `canonical_request.schema.json`: канонический контракт обращения для региональных адаптеров.
- `event_catalog.md`: конверт интеграционного события, каталог и правила совместимости.
- `model_stack.md`: фиксированный целевой стек моделей пилота, топология serving, резервные пути и условия продвижения.
- `ask-pulse.schema.json` и `analytics-intent.schema.json`: версионированные JSON Schema ответа/экспорта Ask Pulse и частного inference gateway; `openapi.yaml` содержит маршруты оператора.
- `adr/`: решения, сохраняющие первый промышленный выпуск небольшим и заменяемым.
- `diagrams/`: архитектурные диаграммы на основе того же дизайна, что и спецификация.

## Зафиксированные решения

1. Бизнес-модули начинают как модульный монолит. Вывод моделей и фоновая работа выполняются отдельными процессами, поскольку масштабируются и отказывают иначе.
2. PostgreSQL, PostGIS и pgvector образуют транзакционное и поисковое ядро, пока измеренная нагрузка не обосновывает другую базу.
3. Каждая региональная система подключается через стабильный канонический контракт и изолированный адаптер.
4. История жизненного цикла только дополняется. Текущее состояние — производный снимок для быстрого чтения.
5. ИИ предлагает. Человек подтверждает маршрутизацию, смену приоритета, принадлежность дубля и сгенерированные ответы.
6. Отсутствующие и неоднозначные даты остаются такими. Конвейер фиксирует качество времени и не выдумывает точность.
7. Целевой пилот начинается с XLM-RoBERTa, BGE-M3, BGE reranker v2 m3, Qwen3 8B и Whisper large v3 turbo за заменяемыми serving-контрактами.

## Проверка

Выполняйте в CI:

```bash
python -c "import json; json.load(open('canonical_request.schema.json', encoding='utf-8'))"
python -c "import yaml; yaml.safe_load(open('openapi.yaml', encoding='utf-8'))"
```

Добавьте OpenAPI linter и тесты контрактов JSON Schema в репозиторий реализации. Тесты адаптеров должны воспроизводить обезличенные fixtures источников и проверять идемпотентность, часовые пояса, карантин и двустороннее сопоставление статусов.
