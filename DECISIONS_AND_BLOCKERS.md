# Решения и внешние блокеры Pulse 109

Здесь зафиксированы границы проекта и ответы, которые **не может придумать команда разработки**. Текущее поведение работающего демо уточняется в [матрице функций](docs/FEATURE_STATUS.md); исследовательская модель или запланированная интеграция не считаются запущенным модулем.

## Принятые архитектурные решения

| Область               | Решение                                                                                                      | Когда пересматривать                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| Продукт               | Слой помощи поверх региональных систем 109; их CRM не заменяется.                                            | Только по решению владельца продукта.                                                       |
| Backend               | Модульное ядро FastAPI.                                                                                      | Делить на сервисы лишь при измеримой нагрузке или доказанной организационной необходимости. |
| Хранилище             | PostgreSQL — источник истины; PostGIS и pgvector доступны для геоданных и поиска.                            | Новый движок — после репрезентативного benchmark.                                           |
| Надёжность            | Транзакционный outbox и идемпотентные адаптеры.                                                              | Брокер возможен после пилота, если есть измеримая потребность.                              |
| Контроль человека     | Маршрутизация, приоритет, состав инцидента и ответы требуют подтверждения оператора.                         | Автоматизация — только после утверждённой политики и доказательств качества.                |
| Классификация         | В runtime работает CPU/лексический fallback; исследовательские baselines не закрывают fine-tuning по ТЗ.     | Нужны исходные тексты и разметка `B02`, таксономия `B06`.                                   |
| Поиск похожих случаев | В runtime есть явно обозначенный fallback. BGE/E5 и reranker — кандидаты, не доказанное production-качество. | Нужны пары дублей, одобренный корпус и оценка `B02/B04`.                                    |
| Генерация             | Произвольная генерация ответов не входит в пилот; заготовки опираются на подтверждённые факты.               | После пилота и отдельного согласования.                                                     |
| Прогноз               | Простой baseline и исследовательские кандидаты, с отказом при недостаточной истории.                         | Победителя определяет проверка на одобренных данных, а не обещание в интерфейсе.            |
| Развёртывание         | OCI-контейнеры; локальный Compose и конфигурации для целевого окружения.                                     | Реальный профиль хостинга и сеть ждут `B08`.                                                |
| Оборудование          | Максимум два GPU, ручной и CPU-пути остаются рабочими.                                                       | Конкретная конфигурация ждёт `B09`.                                                         |

## Известные факты о предоставленных данных

- 12 файлов содержат 1 063 216 физических строк; каноническая обработка CSV дала 1 036 858 строк, сверка ID — 990 032 записи.
- Есть история **7 из 20 регионов**; Павлодар даёт около 67,3% наблюдаемого объёма. Срезы и уровни детализации нельзя просто сложить.
- У 37 канонических записей нет корректной деловой даты. Названия статусов, поля и временная семантика различаются по источникам.
- Исходного текста граждан или стенограммы нет ни в одной из восьми исторических выгрузок, что подтверждено полным проходом 2026-09-13.

Перед использованием этих чисел в официальном отчёте пересчитайте их по фактически предоставленному набору. Синтетическое демо не заполняет недостающие регионы.

## Что команда может решить сама

Внутренние имена пакетов, выбор тестовых инструментов, обратимые локальные улучшения и композицию UI — если они сохраняют контракты, безопасность, доступность и ручной путь.

**Требуют отдельного подтверждения:** публичные поля API и значения статусов, хранение или передача персональных данных за утверждённой границей, новая authoritative-БД, автоматическая маршрутизация или слияние, выбор реального регионального протокола, обязательные SLA/RPO/RTO/retention и необратимые миграции.

Материальные решения фиксируются в [журнале решений](docs/DECISION_LOG.md): контекст, альтернативы, причина, затронутые контракты, способ отката и владелец согласования.
