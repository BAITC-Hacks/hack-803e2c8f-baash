# Алғашқы іске асыруға арналған тапсырма

> M0/M1 кезеңдеріне арналған тарихи тапсырма. Оны қазіргі платформаны қайта құру үшін қолданбаңыз. [Қазіргі құжаттама индексін](../README.kk.md) қараңыз.

Осы репозиторийдегі ережелер мен іске асыру жинағын қолданып, Pulse 109 жүйесін жасаңыз.

Алдымен мына файлдарды ретімен оқыңыз:

1. `AGENTS.md`
2. `CODEX_IMPLEMENTATION_HANDOFF.md`
3. `DECISIONS_AND_BLOCKERS.md`
4. `ACCEPTANCE_MATRIX.md`
5. `contracts/openapi.yaml`
6. `contracts/canonical_request.schema.json`
7. `contracts/event_catalog.md`

Содан кейін репозиторийдің қазіргі күйін және Git күйін тексеріңіз. Репозиторийді бос деп есептемеңіз және пайдаланушының бар жұмысын қайта жазбаңыз.

Алғашқы мақсат — M0, одан кейін M1. Нақты орындау жоспарын құрыңыз, бірақ әдеттегі таңдауларда тоқтап қалмай жұмысты жалғастырыңыз. Жетіспейтін жауап деректерге жауапкершілікті, қауіпсіздікті, қайтымсыз схеманы, API үйлесімділігін немесе алғашқы интеграция нысанасын өзгерткенде ғана сұрақ қойыңыз. Өзге белгісіздерге құжатталған қауіпсіз бастапқы шешімді қолданыңыз, болжамды тіркеп, жалғастырыңыз.

Осы орындауда қажет нәтижелер:

- мақсатты құрылымға сай жұмыс істейтін репозиторий қаңқасы;
- тәуелділіктер мен images дайын болған соң сыртқы желіге тәуелді емес, қайталанатын жергілікті іске қосу;
- репозиторий түбірінен орындалатын build, lint, typecheck, test және contract-test командалары;
- PostgreSQL, PostGIS және pgvector әзірлеу қызметтері;
- тексеру тесттерімен байланыстырылған нұсқаланатын канондық контракттар;
- деректердің шығу тегін, карантинді және жетіспейтін уақытты сақтайтын бастапқы деректен канондық форматқа импорт қаңқасы;
- алғашқы дерекқор миграциялары;
- орындалған командалар, нәтижелер, қалған кедергілер және нақты келесі кезең жазылған `IMPLEMENTATION_STATUS.md`.

Production моделін оқытпаңыз және ұйымдастырушылар бермеген деректерді ойдан қоспаңыз. Тест үшін ғана анық белгіленген синтетикалық деректерді пайдаланыңыз. Қолмен орындалатын негізгі жол алғашқы күннен жұмыс істеуі тиіс.

M0 және M1 қабылдау тексерулерінен өткен соң diff ішінде контракттың ауытқуын, деректердің ашылып кетуін, кездейсоқ тығыз байланыстарды және жетіспейтін қате күйлерін тексеріңіз. Орындауды аяқтамас бұрын маңызды мәселелерді түзетіңіз.
