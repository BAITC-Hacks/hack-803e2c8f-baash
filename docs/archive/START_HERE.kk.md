# Осы жерден бастаңыз

> Бастапқы іске қосуға арналған тарихи нұсқаулық. Оның кезеңдер жөніндегі нұсқаулары [қазіргі құжаттама индексімен](../README.kk.md) және [мүмкіндіктер матрицасымен](../submission/FEATURE_STATUS.kk.md) ауыстырылған.

## Бастапқы спецификация жеткілікті ме

Бұл — архитектурасы жақсы құжатталған материал, бірақ оны бір үлкен әзірлеу тапсырмасы ретінде қолдануға болмайды. Ол алғашқы пилотты да, бүкіл елге арналған мақсатты жүйені де сипаттайды, тек ұйымдастырушылар шеше алатын тәуелділіктерді қамтиды және орындалу ретін оқырманның өзіне қалдырады.

Осы жинақ оны Codex орындай алатын жұмыс тәртібіне айналдырады.

## Жинақты қалай қолдану керек

1. Жинақ мазмұнын жаңа немесе қолданыстағы Git репозиторийінің түбіріне орналастырыңыз.
2. Codex жобаның тұрақты ережелерін автоматты жүктеуі үшін `AGENTS.md` файлын репозиторий түбірінде сақтаңыз.
3. Codex-ті репозиторий түбірінен іске қосып, оған `START_CODEX_PROMPT.md` мәтінін беріңіз.
4. Алғашқы орындауда M0 аяқталып, қарап тексеруге болатын жоспар мен жобаның бастапқы құрылымы дайындалуы тиіс.
5. Кезеңдерді ретімен орындаңыз. Репозиторий дайын болған соң әр кезең үшін бөлек чат немесе worktree қолданған дұрыс.
6. Нақты деректер жиынын Git-тен тыс, қолжетімділігі бақыланатын жолда сақтаңыз. Манифесттерді, схемаларды және жасырындандырылған тест деректерін ғана commit жасаңыз; нақты пайдаланушылардың PII деректерін ешқашан қоспаңыз.

## Codex қолданатын файлдар

- `AGENTS.md`: репозиторийдің қысқа, тұрақты ережелері.
- `CODEX_IMPLEMENTATION_HANDOFF.md`: орындалу реті және инженерлік шешімдер.
- `DECISIONS_AND_BLOCKERS.md`: бекітілген, белгісіз және болжап шешуге болмайтын мәселелер.
- `ACCEPTANCE_MATRIX.md`: әр кезеңді аяқтау үшін қажет дәлелдер.
- `contracts/`: орындалатын OpenAPI, JSON Schema, оқиғалар және ADR.
- `docs/`: толық техникалық спецификация және бейнеленген архитектура.

## Не істеуге болмайды

- Бос чатқа тек 40 беттік PDF беріп, бүкіл жүйені жасауды сұрамаңыз.
- Барлық модульді бір тексерілмеген diff ішінде жасатпаңыз.
- Бастапқы мәтін, белгілер және бекітілген тест жиыны дайын болмайынша модель сапасын мәлімдемеңіз.
- Тестілік өңірлік интеграцияны үнсіз нақты production интеграциясы деп көрсетпеңіз.
- Өтініштердің нақты бастапқы payload деректерін Git-ке, тапсырма мәтініне, журналдарға немесе скриншоттарға сақтамаңыз.
