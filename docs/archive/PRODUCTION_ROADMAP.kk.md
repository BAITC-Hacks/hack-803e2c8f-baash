# Өндірістік платформаны аяқтау

> **Тарихи жоспарлауды бағалау (26 қыркүйек 2026 ж.).** Төмендегі пайыздар мен аяқтау туралы шағымдар орналастыру сертификаты емес, сол күннен бастап сапалы бағалау болып табылады. Ағымдағы [мүмкіндік-күй матрицасы](../submission/FEATURE_STATUS.kk.md) және [demo runbook](../demo/DEMO_RUNBOOK.kk.md) тексерілген әрекетті және кедергілерды сипаттайды.

Платформаның қай жерде тұрғанын және қалған инженерлік-техникалық жұмыстарды немен жабатынын, құжатқа байланысты емес, мемлекет бізге әлі берген жоқ.

Бағалау күні: 2026 жылғы 26 қыркүйек, `codex/production-platform-20260923` филиалына қарсы.

## Қазірдің өзінде айтарлықтай жабық

- **Төзімді жол.** PostgreSQL, миграциялар, идентификациялық және шығыс жәшіктері, транзакцияның негізгі тұтастығы, қалпына келтіру сынақтары және қауіпсіздік CI орындалды. Жақында жүргізілген толық жергілікті жұмыс 210 сынақты, сонымен қатар келісімшарттарды, E2E, линт, теруді тексеру және құрастыруды қамтыды және PostgreSQL CI кейіннен өтті.
- **Иелік және шешім.** Гео юрисдикция, иеленушінің ұсынысы, ұйымға карта жасау бірлігі, Handoff Guard, бірінші рет қабылдау және қабылдамау агрегаттары, өзгермейтін шлюзді бағалау, модельге байланысты сенімділік саясаты және екі адамдық саясатты жариялау.
- **Бейімделетін қабылдау.** Нұсқаланған саясат, шартты сұрақтар, дәлелдемелер талаптары және UI.
- **Оқиға және нәтиже.** Тұйықталу тұтастығы, қайталану, Outcome Memory шекара, өмірлік цикл және нұсқалау, қарым-қатынастар және топология жұмысы, дәлелді жабу.
- **Replay Lab.** Суреттер, тұрақты сақтау, суретті тексеруге қарсы есеп.
- **Қол қойылған аймақтық бумалар.** Тұрақты белсэмбеддинг және қолтаңбаны қайта тексеру.

## Қалған сегіз блок

Бұл елу шашыраңқы функция емес, бір бағдарлама ретінде реттелген.

### 1. Оқиға графигін және топологияны аяқтаңыз

Commit `0257928` аяқталмаған қарым-қатынас жұмысы ретінде анық белгіленген шұғыл бақылау пункті болды. Толық `merge / split / supersede / related / caused_by / recurrence_of`, нұсқа мен инвариантты тексерулер, тұрақтылық, аудит және outbox және олар үшін қолдануға болатын пайдаланушы интерфейсі.

### 2. Таңбаланған бума қарабайырын ғана емес, басқару қабатын аяқтаңыз

Қол қойылған бумалар бар. Өмірлік циклде:

```
draft → validate → sign → stage → activate → last-known-good → rollback
```

Оған қоса шығарылым тарихы, флот күйі, үйлесімділік матрицасы, аймақ бойынша кезеңді шығару және CLI немесе әкімші пайдаланушы интерфейсі. CLI бумасы `0257928` кейін басталып, үзілді.

### 3. Replay Lab UI және босату айырмашылығы

Артқы жағы күшті. Пайдаланушы ескі және жаңа саясатты немесе модельді, өзгертілген шешімдерді, kk / ru / аймақ / санат бойынша регрессияларды, сенімділік интервалдарын, әсер еткен өтініштерды және `BLOCK / CANARY / SAFE TO PROMOTE` үкімін көруі керек.

### 4. Фронтты операциялық сервер ұшына соңына дейін жалғаңыз

Handoff, адаптивті қабылдау және жабу элементтері бар. Оператордың толық сапары үздіксіз болуы керек:

```
queue → appeal → required evidence → ownership → gateway assessment
      → decision → assignment → handoff outcome → incident → resolution → closure
```

Өндіріс болып көрінетін, бірақ орындарда дәлел немесе демонстрациялық көрініс ретінде әрекет ететін беттер жоқ.

### 5. Бақылану және SRE деңгейі

Дайын өнім OpenTelemetry стекі дәлелденбейді. Осы жерде маңызды болып табылатын түпкілікті жолдарды, Prometheus көрсеткіштерін, бақылау тақталарын, құрылымдық журналдарды және операциялық сигналдарды қосыңыз: outbox-тың кешігуі, адаптердің кешігуі, PII кіру аудиті, шлюзден бас тарту, қайта анықтау жылдамдығы, бірінші өтуді қабылдау, қайта ашу жылдамдығы, қайталану жылдамдығы, қате бюджеттері және ескертулер.

### 6. Қатты өндіріс серпімділігі

Қалпына келтіру сынағы бар, бұл нақты прогресс. Әлі де жоқ: жүктеу сынақтары, сіңіру сынақтары, жұмысшының бұзылуы және қайта іске қосылуы, дерекқор қосылымының таусылуы, адаптердің күту уақыты, қорытынды шығарудың үзілуі, нысанды сақтаудың тоқтауы, бір уақыттағы оператор қақтығыстары, кері тасымалдау сынағы, нашарлаған режим сынағы және хаос сценарийлері.

Бар «бақытты жол жұмыс істейді» емес. Жолақ «жүйенің жартысы бұзылды және шағым жоғалмады».

### 7. Қауіпсіздікті өңдеу

Жеткізу тізбегі жұмыс істейді. Нақты өндіріс алдында: қосымша зиянды бағдарлама және MIME сканерлеуі, құпиялар және KMS интеграциясы, кілттерді айналдыру, mTLS немесе балама ішкі аутентификациясы бар қызмет сәйкестіктері, жылдамдықты шектеу, ресурс шектеулері, CSP және қауіпсіздік тақырыптары, RLS және авторизация сынақ жинағы және қауіп үлгісі.

### 8. Өндірісті орналастыру профилі

Құжат емес, профиль ретінде жоғарыда орындалатын орналастыру мақсаты.

## Қалған ең үлкен бөлік код емес

Нақты әлемдегі тік кесінді. Біз әдейі аймақтық API, таксономия мен SLA саясатын, өндіріс OIDC және хостингті немесе деректерді өңдеудің заңды ережелерін ойлап таппадық, себебі ол артефактілер ұсынылмаған.

Олар келгенде, қайта құру емес, байланыс қалады:

```
real 109 source → real ingest → PII vault and redaction → canonical appeal
  → ownership and policy → operator → real regional adapter
  → municipal backend → status reconciliation → resolution evidence
  → verified closure
```

Бұл тамаша инженерлік прототиптен нақты өндірістік ұшқышқа көшу.

## ML әлі өндірістік AI емес

Біз дәлелдемелерді жасаудан дұрыс бас тарттық: күмәнді корпус жабылды, есептер тексерілмеген деп белгіленді және Outcome Memory бекітілген корпуссыз нәтижені қайтарудан бас тартты.

Мұнда және өндіріс ML арасында әлі не бар:

```
production routing dataset → leakage audit → temporal splits
  → multilingual kk/ru/mixed evaluation → calibration → OOD
  → fairness and slices → shadow → replay → canary → registry and promotion
```

Шешімге дейінгі нақты шикі өтініш мәтінінсіз, маршруттау үлгісі өндіріс деңгейінде деп шынайы мәлімдеме жасау мүмкін емес. Бұл синтетикалық модельдермен жұмыс істемеуі керек.

## Құпиялылық өндіріс блогы болып қала береді

Тиісті архитектуралық шектеу қазірдің өзінде бар: азаматтық пішін желідегі ақаулық кезінде өтініш қабылданды деп көрсетпейді, ал нақты мекенжай немесе жеке жіберу бекітілген жеке сақтаусыз белсендірілмейді.

Қалған нәрсе - нақты құбыр:

```
PII Gateway → detection → tokenization → encrypted vault
  → purpose-limited reveal → retention and deletion → access audit
```

Бұл жерде детерминирленген KZ танушылары, контекстік PII детекторы және басқарылатын псевдонимизация жатады.

## Түйіндеме

Инженерлік жұмыстың шамамен 15-20 пайызы осы жерде және өте күшті платформа арасында тұрады. Шамамен 35-45 пайызы осы жерде және нақты мемлекеттік өндіріс арасында тұрады, ал қалғанның маңызды бөлігі қанша код жазылғанына емес, сыртқы келісімшарттарға, деректер мен операцияларға байланысты.

`0257928` шұғыл тексеру пункті болды. Оқиға қатынастары және CLI бумасы бойынша жұмыс одан кейін жалғасты, сондықтан оны аяқталған шығарылым ретінде қарастыруға болмайды.
