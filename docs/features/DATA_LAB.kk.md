# Urban Intelligence / Data Lab

## Шешетін мәселесі

Панель басшыға сан көрсетеді, бірақ оған сенуге бола ма, не алынып тасталған және оны қандай жағдайлар қалыптастырғанын түсіндірмейді. Өтініштерді бағыттайтын қызметте тексерілмейтін көрсеткішті қате қолдану оңай.

## Үш деңгей

```
Data Lab              offline exploration of approved historical datasets
Operations analytics  what the live platform looks like right now
Drill-down            from any figure to the appeals behind it
```

## Желісіз зерттеу

`make eda` канондық деректер жиынында `analytics.offline.report` іске қосып, `CURRENT.md` және `CURRENT.json` жазады. Қайталанушылық құрылымға енгізілген: бір файл бір есеп береді, ал есеп іске қосуларды дұрыс салыстыру үшін оқыған мазмұн хешін тіркейді.

Нақты жазбалар репозиторийге кірмейді. Әдепкіде сақталған синтетикалық fixture қолданылады. Нақты деректер үшін `INPUT` ішінде репозиторийден тыс бекітілген жиынды көрсетіңіз.

```bash
make eda INPUT=/secure/data/canonical.jsonl OUTPUT=/secure/reports/eda
```

Есеп шығу тегінен басталады: жолдар, схема мен сәйкестік нұсқалары, адаптерлер, өңірлер және қамтылған кезеңдер. Деректер негіз берсе, екі ескерту автоматты қосылады: өңірлер әртүрлі кезеңдерді қамтиды; жазбаларда азамат мәтіні жоқ.

## Деректер сапасының өлшемдері

Әр өңірге алымы, бөлімі және анықтамасы бар алты үлес: толықтық, уақтылық, бірегейлік, схемаға сәйкестік, үйлесімділік және шығу тегі.

Бір жалпы балл мұны алмастырмайды. 72% артында жоқ мекенжайлар, сәйкестендірілмеген күйлер немесе сенімсіз уақыт болуы мүмкін — жауаптылары бөлек үш мәселе.

«Алдымен осында қараңыз» тек 95%-дан төмен өлшемдерді тізеді. Осындай бөлім 100%-дан басталса, оқырман оны өткізіп жіберуге үйренеді.

## Сенім графикпен бірге беріледі

Сағат пен апта күні бойынша санау тек бизнес-уақыты сенімді жазбаларды қолданады; сенімді үлес қасында көрсетіледі. Тек күні белгілі жазбаны сағат ұясына салу оған бақыланбаған сәтті теліп, сенімді көрінген графикті жалған етер еді.

## Орташа емес, перцентильдер

`time_to_first_decision` және `time_to_first_assignment` қабылдау уақыты сенімді өтініштер бойынша P50, P75, P90 және P95 көрсетеді. Орташа жеңіл жағдайлардың ықпалында қалып, басшы жауап беретін күрделі жағдайларды жасырады.

Перцентильдер nearest-rank тәсілімен есептеледі: әр нәтиже нақты бір жағдайда байқалған мән.

## Негізгі мақсат — бастапқы жазбаларды ашу

Процесс панелі бір когортаның воронкасы емес, тәуелсіз анықталған кезеңдердің снимогы. Шешілген өтініштер қазір `in_progress` емес; мұндай сандарды бөлу 100%-дан асатын жаңылыстыратын пайыз береді. API `share_of_previous` және `largest_drop` мәндерін бос қалдырады, UI нақты сандар мен анықтамаларды көрсетеді.

Әр агрегатта кілт бар. `GET /v1/datalab/drilldown?key=...` бастапқы өтініштерді қайтарады.

```
timeliness 90%
      ↓
quality:timeliness
      ↓
demo-109-light-002 · received_at_quality = missing
```

Қызмет кілтті жабық жиынмен салыстырады және оның мәтінін SQL-ға ешқашан өткізбейді. Аналитика сүзгісі — дерекқорға кіруге әрекет жасалатын ықтимал нүкте; әр қауіпті кілт пішіні сынақпен қамтылған.

## Метриканы түсіндіру

`GET /v1/datalab/definitions` әр метриканың алымын, бөлімін, уақыт негізін, қосылатын және алынатын жазбаларын анықтайды. Әр анықтама алып тастауларды көрсетуі тиіс; сынақ мұны тексереді.

## Деректер сапасы назар лентасында

Өңірдегі сенімді бизнес-уақыт үлесі шектен төмендесе, Operations Center ашу кілтімен `BUSINESS_TIME_QUALITY_LOW` көтереді. Бастапқы жазбалардың нашарлауын бақыламайтын оқиға лентасы басшыға негізсіз сенім берер еді.

## Тұжырым шекаралары

Модуль себеп-салдарды анықтамайды. Өңірлер айырмасы — тіркелген деректер айырмасы; ол қаланы, процесті немесе экспортты көрсетуі мүмкін. Есептер мұны шектеулер бөлімінде айтады.
