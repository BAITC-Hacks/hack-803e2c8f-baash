# Карточка выступающего · Pulse 109

**Маршрут на 4–5 минут.** Держите эту страницу на втором экране. Жирным выделены действия, в кавычках — короткая формулировка для жюри. Полные инструкции и безопасный сброс — в [сценарии демо](DEMO_RUNBOOK.md).

> Перед защитой запустите `uv run python scripts/demo_runtime.py verify` **только если можно сбросить demo-БД**: команда проверит весь путь, затем удалит demo-тома и восстановит исходные примеры. Для проверки без сброса используйте `uv run python scripts/verify_demo_flow.py`.

## 1. Вступление · 20 секунд

**Открыть демо** с лендинга. Покажите метку `DEMO · SYNTHETIC`.

> «Pulse 109 помогает увидеть одну городскую проблему за отдельными обращениями. Записи здесь синтетические; API, PostgreSQL, аудит, очередь событий и worker настоящие. К действующей CRM 109 демо не подключено».

## 2. Ситуация в городе · 30 секунд

**Операционный центр.** Укажите на показатели и график.

> «Это количество записей в текущей demo-БД, а не прогноз. График учитывает только обращения с достоверным временем; исключения не прячутся».

## 3. Обнаружение · 60 секунд

**Поиск возникающих проблем → открыть `EMERGING_PATTERN`.** Покажите карту и развитие группы во времени.

> «Радар заметил близкие сообщения. Он не утверждает, что знает причину. Семантический сигнал на тексте граждан пока недоступен: такого текста нет в предоставленных исторических выгрузках».

## 4. Координация · 60 секунд

**Создать инцидент из кластера → Ситуационная карточка.** Откройте карту, похожие подтверждённые случаи и одно следующее действие.

> «Создание подтверждает человек. Обращения не сливаются: у каждого остаются собственный ID, история и сроки. Карта показывает охват поступивших сообщений, а не всех пострадавших жителей. Рекомендация объясняет свои основания, но не исполняется сама».

Если блок показывает отказ из-за нехватки данных, это не сбой презентации: прочитайте причину и продолжайте.

## 5. Решение и доставка · 60 секунд

**Очередь оператора → обращение → рекомендация → ручное решение → назначение.** Покажите изменение статуса после обновления карточки.

> «Решение сохраняется транзакционно. Доставку выполняет worker через outbox. В демо внешняя квитанция приходит от replay-адаптера, а не от региональной CRM».

## 6. Проверяемая аналитика · 45 секунд

**Ask Pulse → динамика за 7 дней → «Как рассчитано» → «Показать обращения».** При желании покажите PDF/XLSX. Затем откройте **Лабораторию данных**.

> «Ответ — это разрешённый запрос к аналитике PostgreSQL, не число, придуманное языковой моделью. Видно, какие записи попали в расчёт. В Data Lab мы показываем абсолютные значения и качество, а не выдуманную конверсию между разными текущими статусами».

## Короткие ответы на сложные вопросы

| Вопрос                                                    | Ответ                                                                                                                                                    |
| --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Это реальные обращения?                                   | Нет. Данные синтетические и помечены. Рабочий процесс и хранилище настоящие.                                                                             |
| Есть fine-tuned классификатор и embedding по ТЗ?          | Нет подтверждённого runtime и качества на текстах граждан. Сейчас есть fallback и исследовательские кандидаты. Нужен одобренный корпус RU/KK и разметка. |
| Охвачены все 20 регионов?                                 | Нет. Предоставленные исторические данные охватывают семь; остальные источники ждём от организаторов.                                                     |
| AI сам назначает ответственного или объединяет обращения? | Нет. Существенные действия подтверждает человек.                                                                                                         |
| Что будет без ML?                                         | Ручной приём, решение, назначение и аудит продолжают работать.                                                                                           |
| Это готово к публичной работе с персональными данными?    | Нет. Нужны IdP, правовое основание, сроки хранения, рабочие сканирование и региональная интеграция.                                                      |

Не обещайте качество модели, полноту данных или боевой VPS, которых ещё нет. [Подробный аудит](review/COMPETITION_AUDIT_2026-09-29.md) содержит доказательства и вопросы организаторам.
